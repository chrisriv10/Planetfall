# Beyond the Launch + Windows desktop — v0.2.0

- Classic Quick Match finds compatible public lobbies with verified player identity, ready controls, cancellation and bounded optional bot fill.
- How to Play, optional first-match hints and private-room invite links make the existing four families easier to enter and learn.
- Private Career adds newly tracked results and 13 authoritative recognition-only achievements. Existing earned XP, wallets and cosmetics are preserved; historical matches are not invented.
- Results confirm saved progression and provide Career/Find Another Match navigation. Timed draws explain tied integrity correctly.
- Windows x64 installer and portable packages open the canonical online game in a sandboxed Electron shell, with native fullscreen, offline recovery and persistent guest preferences.
- The website favicon and Windows application icon use the Planetfall astronaut's face. The README now documents the current game, real screenshots and development/release workflows.

## Play and install

The browser game is at <https://planetfall.pages.dev/>. Versioned Windows files and SHA-256 checksums are attached to the corresponding [GitHub release](https://github.com/chrisriv10/Planetfall/releases).

Download the NSIS `Planetfall-0.2.0-Setup-x64.exe` for per-user installation, or use `Planetfall-0.2.0-Portable-x64.exe`. Packages are unsigned; Windows may display an unrecognized-app/SmartScreen notice. Check the release source and checksum. No automatic updater is enabled.

Internet and the hosted multiplayer service are required. The desktop app initially supports persistent guest play only. Google sign-in/linking remains browser-only; opening the browser version does not transfer or link the desktop guest profile. Clearing app data can remove access to that guest. Portable builds use the Windows user's app profile rather than promising USB-local progress.

## Hosting and compatibility

Server and Pages client must be released from the same approved main revision. This update needs no database schema migration or new runtime privilege. The existing transactional writer, durable receipts, canonical account mapping and retired-writer fence must remain intact. Keep the corrected rollback build available and never restore an old ledger over newer earned progress.

Deployments end active in-memory rooms. Previously loaded clients should reload after the server is replaced. Public Quick Match is Classic-only and presence/matchmaking are scoped to one authoritative server. The other families remain playable works in progress with solo/private flows.
